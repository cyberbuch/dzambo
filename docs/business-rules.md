# Счетоводни правила (домейн)

Правилата се пренасят **едно към едно** от ytbuch, не се преизмислят.

## Основни принципи

- **Черно сторно** (кредитно известие): отрицателен знак, **без** обръщане на
  Дт/Кт.
- **Постнат документ е immutable** — корекция само със сторно.
- Сумите в JSON са низове; изчисленията са в BigDecimal (без float).
- `company_id` дели данните по фирма.

## Пост на фактура

Контролната сума (клиенти/доставчици) се **извежда от редовете** (`net + ДДС`),
което гарантира балансирана статия (Дт = Кт) дори при неконсистентен хедър.
Продажба: Дт 411 / Кт приходни сметки + ДДС (4532). Покупка: Дт разходна +
ДДС (4531) / Кт 401. Инвентарни стоки: FIFO консумация + COGS (Дт разход /
Кт запасна).

## ДДС

- `vat_period` = месец на счетоводното събитие (не на издаването).
- Ръчни клетки 33/70/71/80/81/82 на декларацията по фирма+период.
- Експорт за НАП: POKUPKI/PRODAGBI/DEKLAR/VIES — фиксирана ширина,
  Windows-1251, CRLF, без заглавен ред; ZIP stored. Ширини: 276/426/592 байта.

## SAF-T

- XML V1.0.1, режими: месец / година / при поискване.
- **Мапинг:** свободен сметкоплан → НАП номенклатури; `AccountID` = НАП код,
  `TaxpayerAccountID` = собствения номер. `accounts.saft_account_type`.
- Валидира се с `xmllint --schema BG_SAFT_Schema_V_1.0.1.xsd` (0 грешки).

## Склад

- Оценка: WAC / FIFO / LIFO (по фирма).
- Ред на движения в деня: начало(0), доставка(1), трансфер(2), производство
  разход(3)/приход(4), ръчно изписване(5), продажба(6).
- `rebuild` преизчислява партиди и наличности; `writeoff` месечно осчетоводява
  продажби (Дт разход / Кт материали), идемпотентно по месец.
- Правила: `stock_account_rules` (goods/production/material).

## Справки

- Оборотна ведомость: 6 колони (НД/НК/ОД/ОК/КД/КК).
- Финансови отчети по **формули** (по фирма): бланки balance/pl/cashflow/equity,
  формули с `+/-`, `@код` референции, сметки с Д/К/ОД/ОК/НД/НК, кореспонденции.
- Стойности — от дневника + начални салда; крайно салдо = начално + оборот.

## Auth

- Argon2id + JWT HS256 (issuer `dzambo`, TTL 7 дни, `ver` на сесията).
- 2FA TOTP (SHA1, 6 цифри, 30 с, прозорец ±1); anti-replay на прозореца;
  lockout след 5 грешки (15 мин); резервни кодове (еднократни).
- Роли с permissions (JSON масив); дефолтни 3 роли.
